# Product feedback and friction log

## F01 — Simulation clarity matters
When a hackathon permits simulated Alexa+ experiences, the demo needs to identify the simulation clearly while still proving the interaction model. LifeDesk labels the simulation in the header and conversational panel rather than implying access to gated Alexa+ tooling.

## F02 — Agent value appears after the summary
Extracting a deadline is useful, but the stronger user value comes from coordinating what should happen next: gather inputs, order tasks, draft a response, propose reminders and keep the chain explainable.

## F03 — Trust requires visible boundaries
For legal, financial and medical-adjacent documents, confidence labels, editable outputs and “propose before execute” are core product primitives, not optional polish.

## F04 — Deterministic samples improve judging
Synthetic examples remove login, network, private-data and document-quality failure modes. That makes the hackathon demo reproducible and allows judges to focus on the agentic workflow.

## F05 — Source/inference separation is essential
A user should be able to tell which detail came directly from the document and which conclusion was generated by the agent. The final audit trail makes that distinction visible.
